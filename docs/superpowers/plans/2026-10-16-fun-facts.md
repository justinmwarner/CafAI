# Fun facts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fun fact under the coach's reply to a dialed-in shot that ran like the last one, from CafAI's checked list or the coach, chosen in Settings (spec: `docs/superpowers/specs/2026-10-16-fun-facts-design.md`, D197-D203).

**Architecture:** Pure modules in `src/coach/facts/` (matcher, picker, told list, "like the last one", wording check) feed the engine (`src/app/engine/`), which decides when a fact is due, tells the coach in the shot event, runs the new auto tool `share_fun_fact`, and shows CafAI's own fact when the coach gives none. The chat renders a `fact` part; Settings > Coach chooses the source. Web search is Anthropic's server tool, carried through the LLM layer and the CafAI Bridge.

**Tech Stack:** TypeScript 5.9, React 19 + MUI 9, zod 4, vitest 5, Playwright, Node 22+ (bridge).

**Base:** branch `feat/fun-facts`, commit with the spec, this plan and the shared groundwork (below). Builders work in worktrees on disjoint files; the owner wants pace: no check-ins, one combined review at the end.

- [ ] **A1 pure modules, test first.** Cases to cover: whole-word, case- and accent-blind matching ("sidama" in "Sidama, Ethiopia", "cafe" in "Café"; "geisha" not in "geishas", since plurals come from the fact's own list; multi-word terms like "pink bourbon"); `notes` as a condition of its own; a general fact fits every bag; picker order (roaster, variety, origin, process, notes, roast level), alternation bag/general, a shuffle seeded by the bag id (stable per bag), told facts skipped, the least recently told first once every fitting fact was told, `null` for an empty list; told list cap, newest kept, bad JSON, `null` storage, `setItem` throwing; `ranLikeLast` each tolerance on both sides, a missing number on either side not compared, stop reasons compared when both known, a new channeling flag; `factWordingError` catches "should taste", "will taste", "you'll taste", "expect", "this cup", "this shot", "your coffee tastes", "your cup" and passes "Kenya's SL28 was selected in the 1930s", "Damascenone is linked to notes described as rose".
- [ ] **A2 facts.json test** (`facts.test.ts`): every fact has the shape; ids unique, kebab-case, at most 60 characters; `about` at most 80; `text` at most 280 and free of `factWordingError`; `source` https; `topic` known; every `flavour` fact has `match.notes`; any °F written is an error and a temperature reads `<number> °C`; match words lower-case. Passes on `[]`.
- [ ] **A3 the tool and the prompt.** `share_fun_fact` in `contract.ts` (in `AUTO_TOOLS`, `TOOL_INPUTS`), its description in `tools.ts`; `buildSystemPrompt(templates, { temperatureUnit, funFacts })`: the "Fun facts" section (spec section 7, and the web lines of section 8 for `'web'`) only for `'coach'` and `'web'`; "Your tools are exactly" lists only the tools on offer (`share_fun_fact` only in those two modes, `web_search` only in `'web'`), and "You cannot browse the web" stays except in `'web'`. `createCoachPort` keeps one prompt per (unit, prompt variant): `'off'` and `'list'` share the plain prompt. The port's `systemPrompt` takes the fun facts source (update `ports.ts` and its fakes).
- [ ] **A4 the engine.** Read `settings.funFacts ?? DEFAULT_FUN_FACTS` at each use. Per run: tools without `share_fun_fact` unless `'coach' | 'web'`; `serverTools: [WEB_SEARCH_TOOL]` for `'web'` unless web search proved unavailable this session. On a shot: `previousLikeShot` + `ranLikeLast` decide if a fact is due (never when `'off'`); due in the coach's modes, the shot event carries `funFact: { told: toldLabels(...), web }`. `share_fun_fact` (any time it is called, due or not): check `factWordingError` (fresh calls only, as `domainError` does), add `{kind:'fact'}` in an assistant message of its own, `source` = `siteOf(input.source)` only in `'web'`, add `coachKey(about)` to the told list, answer `{"shown":true}`. After the model run that answers a due shot, if no fact was shown, `await loadFacts()`, `pickFact(...)`, show it (`source` = `siteOf(fact.source)`) and add its id to the told list, before the run's UI calls (the taste question) are presented; a run that failed keeps it due for the retry; a new shot clears it. A run that fails with `webSearchUnavailable(error)`: run again at once without the server tool, a notice once ("Web search is not available for your Anthropic account, so the coach shares what it knows."), and no web search for the rest of the session. The told list comes from `createServices` (`createToldList(deviceStorage)`) as a new engine dependency, an in-memory list when absent (tests).
- [ ] **A5 the scripted coach.** On a shot event with `funFact`: the first fact of `facts.json` (static import is fine in mock code) that `factFits` the bag (from the context block's `bag` or the saved bag details) with an origin match and whose `coachKey(about)` is not in `told`: call `share_fun_fact` with it (`source: null`) beside the text and the taste `ask_user`, in that order; else no call. Its tests and the demo voice tests stay green.
- [ ] **A6 docs in your files**: `ENGINE_PROTOCOL.md` rule 3 (`funFact`), a new rule for `share_fun_fact` and its result, the scripted fake's part. Comments cite D197-D203 as the spec numbers them.
- [ ] **A7 verify and commit**: `npm run typecheck`, `npm run lint`, `npm run test` all green; one commit `feat: fun facts' core ... (D197-D201)`.
